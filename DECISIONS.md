# Decisions

Choices the spec left open, or where the implementation deliberately deviates. Newest at the bottom.

| Date | Area | Decision | Why |
| --- | --- | --- | --- |
| 2026-10-28 | Name | Kept the working title **Parlo**. | Spec default; easy to rename (brand component, manifest, page titles). |
| 2026-10-28 | Deployment | Caddy is the stack's single entry point but is published on **127.0.0.1:7892 (HTTP)** behind the host's **Nginx + Certbot**, like AutoMail, ScoreSage and IT Desk. `docker-compose.standalone.yml` lets Caddy take 80/443 and get certificates itself on a box without a reverse proxy. | The shared VPS already runs Nginx on 80/443, so Caddy can't bind them; this keeps the spec's Caddy routing and HTTPS requirement while matching the box's existing flow. Ports 7888–7891 are taken. |
| 2026-10-28 | Default models | Gemini `gemini-3.8-flash` for conversation, feedback, lesson content and STT. Anthropic defaults: `claude-haiku-5-5` (conversation), `claude-sonnet-5-5` (feedback/content). | The same Gemini model the other apps on this box use. All are overridable per task in `.env` or the admin panel — pick after comparing quality and cost (open question in the spec). |
| 2026-10-28 | Provider adapters | Every adapter talks plain HTTP via httpx (no vendor SDKs). | One dependency to mock in tests; no SDK version churn. |
| 2026-10-28 | Structured output | JSON mode + a schema described in the prompt + Pydantic validation with one corrective retry, instead of provider-specific schema features. | Works identically across all five LLM providers. Lesson exercises are validated one by one so a single bad item is dropped instead of failing the lesson. |
| 2026-10-28 | Runtime config | Admin overrides (providers, models, voices, keys, pricing, budget) are stored in `app_settings` and layered over `.env`, cached 10 s per process. Admin-entered API keys are stored in the database in plain text and shown masked. | Lets you switch providers without redeploying, as the spec asks. The database lives on your own server; `.env` keys remain the default. |
| 2026-10-28 | FSRS | In-repo FSRS-5 implementation (default parameters, 90 % retention, 1 m/10 m learning steps, 10 m relearning, interval fuzz). | Small, fully tested, and the card state format is ours. Optimising parameters per user is a possible later addition. |
| 2026-10-28 | New cards | Recognition cards are introduced first, then listening/kanji, then production; mistake cards are never capped by the new-cards-per-day limit. | Recognise before you produce; mistakes should come back quickly. |
| 2026-10-28 | Answer checking | Typo tolerance never forgives short words (≤ 3 letters: articles, pronouns, particles) or differences confined to a word's last two letters (conjugation/agreement). Accent-only differences are "almost correct". Free translations that don't match are judged by the LLM, cached per answer. | Keeps grammar errors from being waved through as typos. |
| 2026-10-28 | Lesson flow | Wrong answers get one second try at the end of the lesson; accuracy counts first attempts only. Tests (checkpoints, level tests, kana tests) need 80 %. | Common, encouraging pattern without inflating scores. |
| 2026-10-28 | Unlocking | Levels up to the enrolment's current level are open; earlier levels are fully open for revision; the current level is a path (each lesson unlocks the next, the checkpoint gates the next unit). A level test can always be taken to test out. Japanese A1+ stay locked until both kana scripts are done or their tests passed. | Matches the spec's path + placement + manual unlock. |
| 2026-10-28 | Checkpoints & level tests | Generated by the LLM from the unit/level skeletons (one call each), not assembled from existing lesson exercises. | Works even when you jump ahead and earlier lessons were never generated. |
| 2026-10-28 | Kana module | Built deterministically from `curriculum/ja_kana.yaml` (mnemonics, words using only taught kana) — no LLM. | Free, instant, and correct by construction. |
| 2026-10-28 | Furigana | The LLM writes Japanese with `{漢字|かな}` markup; the frontend renders `<ruby>`, derives kana-only answers and romaji (Hepburn) from it. "Only new kanji" hides readings for kanji that appear in words you've learned. | One format for every Japanese string; answers in kana or kanji are both accepted. |
| 2026-10-28 | Conversation feedback | Runs in the worker after each message and is pushed back over the WebSocket via Redis pub/sub; the reply is never delayed. Goal detection for scenarios is an extra `goal_achieved` field in the same feedback call. | Async as the spec requires, without an extra LLM call per turn. |
| 2026-10-28 | TTS streaming | Reply text streams token by token; each finished sentence is synthesised concurrently and played in order as it arrives. Slow replay re-synthesises the whole message at 0.75×. | Fast first audio while keeping playback ordered. |
| 2026-10-28 | Pronunciation flags | Word-level diff of the transcript against the corrected sentence, excluding fragments already explained by a grammar error, plus `[?]` and low-confidence words. Always labelled approximate. | The spec's approach; keeps grammar mistakes from being blamed on pronunciation. |
| 2026-10-28 | Audio cache key | sha256(provider + voice + language + speed + text). Speeds snap to 0.75 / 1 / 1.25. | The spec's key plus the provider, so switching providers never serves the wrong voice. |
| 2026-10-28 | Daily goal | One goal per user (XP or minutes) across all languages, instead of per enrolment. Days follow the user's time zone (from the browser). Streak freeze: one per ISO week, applied automatically to a single missed day. | Simpler to reason about when learning several languages. |
| 2026-10-28 | Offline | Service worker caches the app shell, static assets, TTS audio, and the last fetched lessons, course map and review queue. Offline answers are checked locally (normalisation and accents); lesson completions and reviews are queued in localStorage and replayed on reconnect. Conversations need a connection. | "Offline-friendly for already-downloaded lessons and reviews". |
| 2026-10-28 | Placement test | A 30-item multiple-choice bank per language is generated once (admin can regenerate). The test starts at A2, moves up or down a level after two right or two wrong answers, and stops after 15 questions or when the boundary is found. | Adaptive, ~15 questions, one LLM call per language ever. |
| 2026-10-28 | Lesson generation timing | Just-in-time with look-ahead: opening a lesson generates it (~20–40 s the first time) and the worker keeps the next `PREGENERATE_AHEAD` lessons ready. Admins can pre-generate a whole level from the content browser. | Avoids the ~$30–80 upfront cost of bulk generation (open question in the spec); you can still opt in per level. |
| 2026-10-28 | Sessions & CSRF | Opaque session token in an HTTP-only SameSite=Lax cookie (hash stored in Postgres, 30 days), double-submit CSRF token header on unsafe requests, Origin check on the WebSocket. | Standard cookie-auth hardening without a JWT. |
| 2026-10-28 | Python / Postgres versions | Python 3.13 base image; PostgreSQL 18 (volume mounted at `/var/lib/postgresql`, the 18+ layout). | Latest versions with wheels for both amd64 (VPS) and arm64 (dev machine). |
| 2026-10-28 | Fonts | Inter (UI) and Noto Sans JP self-hosted via Fontsource; the Japanese font is split by unicode-range, so it only downloads when Japanese text is on screen. | "Loaded only when needed" without extra code. |
| 2026-10-28 | Flags | Inline SVG flags instead of emoji. | Windows doesn't render flag emoji. |
| 2026-10-28 | Web push | VAPID keys generated on first boot when not in `.env`; reminders sent hourly at each user's chosen local hour if they haven't practised that day. | Zero-config push. |
| 2026-10-29 | YAML booleans | Curriculum YAML is read with a loader that treats only `true`/`false` as booleans; `yes`, `no`, `on` and `off` stay strings. Kana lessons built from the old data are rebuilt on their next visit, and the migration repairs mistake cards that stored `False`. | PyYAML follows YAML 1.1, so the romaji `no` (の) became `False` and the French `on` became `True`. |
| 2026-10-29 | Short Japanese audio | Japanese clips of up to 4 characters (single kana, short words) get a `。` appended and use a Google Neural2 voice instead of the configured one. A kana entry can name what to say aloud (っ is read as きって). | Chirp 3 HD voices return silence or noise for one- or two-character input; Neural2 reads them reliably. |
| 2026-10-29 | Practice by level | Review cards record the level and unit they were learnt in. Review and Learn can practise a whole level (Kana, A1, A2…) or one unit at any time, whether cards are due or not; ratings still go through FSRS. Finished kana lessons add one review card per character. | "Review what I've learnt so far" per level without breaking the schedule — FSRS accounts for reviewing early. |
| 2026-10-29 | WebSocket origin | The conversation WebSocket accepts an Origin matching the Host, `X-Forwarded-Host` or `DOMAIN`. Rejections accept and then close with 4401 (signed out) or 4403 (origin), so the app shows a clear message instead of retrying forever; model errors show the provider's message with a retry. | A proxy that rewrote Host (Nginx `proxy_set_header` inheritance) made every conversation hang on "reconnecting". |
| 2026-10-29 | Attempt history | Exercise attempts keep their row when a lesson is regenerated (the exercise reference becomes NULL). | Rebuilding a lesson shouldn't erase your answer history. |
| 2026-10-29 | Overloaded models | When the main model answers 429/5xx (Gemini's 503 "high demand") a streamed reply hasn't started within 12 s, or a transcription takes over 12 s (24 s with combined feedback), the call moves to a backup model (`LLM_MODEL_FALLBACK`; Gemini default `gemini-3.5-flash-lite`, the fast model the IT Desk app on the same box uses). The overloaded model is tried second for the next five minutes (shared by replies and transcription). Without a backup the same model is retried once. Conversations show "switching to the backup model…" in the typing bubble and stop waiting after 70 s of silence. | A busy spell on one model shouldn't stall every conversation; trying a lighter model is faster than waiting it out. |
| 2026-10-29 | Faster voice turns | Gemini transcription moves to the backup model after 12 s, transcribes with minimal thinking (1–3 s faster per clip, measured), and shares the overload cooldown with replies, so one busy model sends both to the backup for five minutes. Non-streamed calls have time limits too (20 s conversation tasks, 45 s feedback, 150 s lesson content). | Measured on 2026-10-29: `gemini-3.8-flash` hung ~60 s per call while `gemini-3.5-flash-lite` replied in ~1 s; waiting out a hung model made every voice turn slow. |
| 2026-10-29 | Practice modes | Practice picks lesson blocks from the course map (by level and unit, up to 20 items, course order or shuffled) and runs as flashcards or "Type it": meaning → type the word, kana → type the romaji. One letter off (or only accents) on answers of 3+ letters is "close" with one more try; a miss comes back two items later; two right in a row clears the item. The first attempt at each item is rated into FSRS (right 3, right after close 2, wrong 1). Romaji answers accept common spellings (si/shi, tu/tsu, hu/fu). | Language Perfect-style drilling the user asked for. Short answers like "ka"/"ki" are different syllables, so one letter off there is wrong, not close. A block includes the words the user learnt in it even after the lesson is regenerated. |
| 2026-10-29 | Background translation | Every conversation message (the AI's and the learner's) is translated as soon as it's saved and pushed to the page, so Translate opens instantly; a click while it's still running joins the same request. Tutor-mode replies (mostly English) are skipped. | Translation was a separate slow call made only on click. The cost is one small call per message. |
| 2026-10-29 | Shared overload cooldown | The "skip the overloaded model" memory lives in Redis (`overloaded:<provider>:<model>`, 5 min) as well as in each process, so the worker's feedback skips a model the API already found overloaded. The worker runs up to 8 jobs at once so feedback doesn't queue behind lesson generation. | Feedback was slow on the first message of a busy spell because the worker had to discover the overload itself. |
| 2026-10-29 | Loose course order | "Course order" practice lets each item drift up to 3 places, and repeats come back after a random 2–3 (miss) or 3–5 (first hit) items. | Follows the course without being the same sequence every time. |
| 2026-11-22 | Kanji layer | Kanji stay taught through words; a character layer is added on top. KANJIDIC2 + KRADFILE (EDRDG, CC BY-SA) are trimmed into `curriculum/kanji.json` (2,395 kanji: Jōyō, JLPT and every course kanji) and loaded into a `kanji` table when the file changes. A lesson shows "New kanji" cards for the kanji whose first appearance in course order is that lesson — worked out at serve time, so no lesson regenerates — placed just before the first exercise that uses each one (a word card counts for its own word only). At most 4 full cards (most frequent first); the rest share one "Also new in this lesson" card, since half the lessons introduce 5–11 kanji. Finishing a lesson adds one `kanji_char` review card per kanji in its words (backfilled for finished lessons). A kanji counts as *known* — and Furigana "New kanji" hides its reading — once that card reaches 3 days' FSRS stability, not when a word containing it was first seen. Memory hooks are written once per kanji by the LLM in a worker job. | The user wanted to read kanji, not write them. Word-first matches how readings work (今 いま / 今日 きょう); the character layer stops look-alikes blurring and makes furigana fade on knowledge rather than exposure. |
| 2026-11-23 | Watch (YouTube) | A shared Watch library: paste a YouTube link and attach a subtitle file (.srt/.vtt/.ass, UTF-8/UTF-16/Shift-JIS; rolling auto-captions collapsed; signs/songs styles skipped). Parlo never downloads from YouTube: videos play in YouTube's official IFrame player (youtube-nocookie host, its own captions unloaded) and subtitles sit below it. A worker job annotates lines in batches of 25 (3 at once) with one LLM call each: furigana markup, hiragana, English and up to 3 key words, plus a CEFR level; a line whose characters the model changed keeps the original text. Three subtitle levels (kanji + reading + English / hiragana / Japanese only) and "pause after each line" are per-person settings. Key words can be saved to the deck and practised at once (Type it with `vocab=ids`). Android can share a YouTube link straight to Parlo (web share target). | YouTube's terms only let owners download captions and forbid downloading audio, so the subtitle file comes from the user; everything else is automatic. |
| 2026-11-23 | Watch (your own files) | Admins (or everyone, `VIDEO_UPLOADERS`) can upload .mp4/.m4v/.mov/.webm/.mkv files up to `VIDEO_MAX_FILE_MB` (2 GB) and `VIDEO_MAX_MINUTES` (60), within a library total of `VIDEO_STORAGE_GB` (25 GB); limits are checked before any bytes are sent. Uploads go in 6 MB pieces (`PUT /videos/uploads/{id}/{n}`), each written to a temp name then renamed, so a dropped connection resumes from the pieces the server has (the browser remembers the upload for the same file). The worker joins the pieces and repackages without re-encoding the picture: H.264 → MP4 (+faststart), VP8/VP9/AV1 → WebM, audio converted only when the container can't carry it; HEVC and other codecs are refused with a "convert to H.264 MP4" tip and the file is deleted at once. Subtitles come from, in order: a file the user attached, a text subtitle track in the course language inside the file, or transcription of 2-minute audio clips with timestamps (Gemini JSON segments or Whisper `verbose_json`), joined into one overlap-free timeline. Then the same annotation as YouTube videos. Files are served with range requests to a plain `<video>`, so subtitles can also sit on the picture, including in full screen. Abandoned uploads are removed after two days. | A small VPS can't re-encode video, but repackaging takes seconds; 6 MB pieces fit under the proxies' 8 MB body limit, so no Nginx change. |
| 2026-11-23 | Reels | Every ready video is cut into 15–45 s clips of whole subtitle lines (a whole video under a minute is one reel). A clip starts only at a new moment — the first line, after a pause of 1 s or more, or (uploaded files) at a keyframe inside a short pause, since encoders put keyframes at cuts — and ends where a sentence finishes, preferring to end with the scene. A plain new sentence starts a clip only in long talk with no pause nearby; a line ending in 、 or a comma never ends one. Each clip gets a level from the video's level, the harder end of its kanji (old JLPT levels, counted double) and its speech rate. The feed (`GET /videos/reels`) targets the learner's course level shifted by Easier −1 / My level 0 / Harder +1 / Challenge +2, then the share of the clip's key words and kanji they know (95 / 80 / 60 / 40%), with a little shuffle; the same video never plays twice in a row and clips seen in the last 3 days (Redis) come last. Clips are re-cut automatically when the rules change (`CLIPS_VERSION`). One player is reused (YouTube `loadVideoById`, or a `<video>`), clips loop, start muted, and tap-to-look-up pauses the clip. | The user asked for clips that start at the beginning of a scene or sentence, so they have context, and that match their level with an option to raise it. "% known" counts the key words the annotation picked plus kanji, not every word, so it reads low for beginners. |
