# Decisions

Choices the spec left open, or where the implementation deliberately deviates. Newest at the bottom.

| Date | Area | Decision | Why |
| --- | --- | --- | --- |
| 2026-10-28 | Name | Kept the working title **Parlo**. | Spec default; easy to rename (brand component, manifest, page titles). |
| 2026-10-28 | Deployment | Caddy is the stack's single entry point but is published on **127.0.0.1:7892 (HTTP)** behind the host's **Nginx + Certbot**, like AutoMail, ScoreSage and IT Desk. `docker-compose.standalone.yml` lets Caddy take 80/443 and get certificates itself on a box without a reverse proxy. | The shared VPS already runs Nginx on 80/443, so Caddy can't bind them; this keeps the spec's Caddy routing and HTTPS requirement while matching the box's existing flow. Ports 7888–7891 are taken. |
| 2026-10-28 | Default models | Gemini `gemini-3.8-flash` for conversation, feedback, lesson content and STT. Anthropic defaults: `claude-haiku-5-5` (conversation), `claude-sonnet-5-5` (feedback/content). | The same Gemini model the other apps on this box use. All are overridable per task in `.env` or the admin panel — pick after comparing quality and cost (open question in the spec). |
| 2026-10-28 | Provider adapters | Every adapter talks plain HTTP via httpx (no vendor SDKs). | One dependency to mock in tests; no SDK version churn. |
| 2026-10-28 | Structured output | JSON mode + a schema described in the prompt + Pydantic validation with one corrective retry, instead of provider-specific schema features. | Works identically across all five LLM providers. Lesson exercises are validated one by one so a single bad item is dropped instead of failing the lesson. |
| 2026-10-28 | Runtime config | Admin overrides (providers, models, voices, keys, pricing, budget) are stored in `app_settings` and layered over `.env`, cached 10 s per process. Admin-entered API keys are stored in the database in plain text and shown masked. | Lets you switch providers without redeploying, as the spec asks. The database lives on your own server; `.env` keys remain the default. |
| 2026-10-28 | FSRS | In-repo FSRS-5 implementation (default parameters, 90 % retention, 1 m/10 m learning steps, 10 m relearning, interval fuzz). | Small, fully tested, and the card state format is ours. Optimising parameters per user is a possible later addition. |
| 2026-10-28 | New cards | Recognition cards are introduced first, then listening/kanji, then production; mistake cards are never capped by the new-cards-per-day limit. | Recognise before you produce; mistakes should come back quickly. |
| 2026-10-28 | Answer checking | Typo tolerance never forgives short words (≤ 3 letters: articles, pronouns, particles) or differences confined to a word's last two letters (conjugation/agreement). Accent-only differences are "almost correct". Free translations that don't match are judged by the LLM, cached per answer. | Keeps grammar errors from being waved through as typos. |
| 2026-10-28 | Lesson flow | Wrong answers get one second try at the end of the lesson; accuracy counts first attempts only. Tests (checkpoints, level tests, kana tests) need 80 %. | Common, encouraging pattern without inflating scores. |
| 2026-10-28 | Unlocking | Levels up to the enrolment's current level are open; earlier levels are fully open for revision; the current level is a path (each lesson unlocks the next, the checkpoint gates the next unit). A level test can always be taken to test out. Japanese A1+ stay locked until both kana scripts are done or their tests passed. | Matches the spec's path + placement + manual unlock. |
| 2026-10-28 | Checkpoints & level tests | Generated by the LLM from the unit/level skeletons (one call each), not assembled from existing lesson exercises. | Works even when you jump ahead and earlier lessons were never generated. |
| 2026-10-28 | Kana module | Built deterministically from `curriculum/ja_kana.yaml` (mnemonics, words using only taught kana) — no LLM. | Free, instant, and correct by construction. |
| 2026-10-28 | Furigana | The LLM writes Japanese with `{漢字|かな}` markup; the frontend renders `<ruby>`, derives kana-only answers and romaji (Hepburn) from it. "Only new kanji" hides readings for kanji that appear in words you've learned. | One format for every Japanese string; answers in kana or kanji are both accepted. |
| 2026-10-28 | Conversation feedback | Runs in the worker after each message and is pushed back over the WebSocket via Redis pub/sub; the reply is never delayed. Goal detection for scenarios is an extra `goal_achieved` field in the same feedback call. | Async as the spec requires, without an extra LLM call per turn. |
| 2026-10-28 | TTS streaming | Reply text streams token by token; each finished sentence is synthesised concurrently and played in order as it arrives. Slow replay re-synthesises the whole message at 0.75×. | Fast first audio while keeping playback ordered. |
| 2026-10-28 | Pronunciation flags | Word-level diff of the transcript against the corrected sentence, excluding fragments already explained by a grammar error, plus `[?]` and low-confidence words. Always labelled approximate. | The spec's approach; keeps grammar mistakes from being blamed on pronunciation. |
| 2026-10-28 | Audio cache key | sha256(provider + voice + language + speed + text). Speeds snap to 0.75 / 1 / 1.25. | The spec's key plus the provider, so switching providers never serves the wrong voice. |
| 2026-10-28 | Daily goal | One goal per user (XP or minutes) across all languages, instead of per enrolment. Days follow the user's time zone (from the browser). Streak freeze: one per ISO week, applied automatically to a single missed day. | Simpler to reason about when learning several languages. |
| 2026-10-28 | Offline | Service worker caches the app shell, static assets, TTS audio, and the last fetched lessons, course map and review queue. Offline answers are checked locally (normalisation and accents); lesson completions and reviews are queued in localStorage and replayed on reconnect. Conversations need a connection. | "Offline-friendly for already-downloaded lessons and reviews". |
| 2026-10-28 | Placement test | A 30-item multiple-choice bank per language is generated once (admin can regenerate). The test starts at A2, moves up or down a level after two right or two wrong answers, and stops after 15 questions or when the boundary is found. | Adaptive, ~15 questions, one LLM call per language ever. |
| 2026-10-28 | Lesson generation timing | Just-in-time with look-ahead: opening a lesson generates it (~20–40 s the first time) and the worker keeps the next `PREGENERATE_AHEAD` lessons ready. Admins can pre-generate a whole level from the content browser. | Avoids the ~$30–80 upfront cost of bulk generation (open question in the spec); you can still opt in per level. |
| 2026-10-28 | Sessions & CSRF | Opaque session token in an HTTP-only SameSite=Lax cookie (hash stored in Postgres, 30 days), double-submit CSRF token header on unsafe requests, Origin check on the WebSocket. | Standard cookie-auth hardening without a JWT. |
| 2026-10-28 | Python / Postgres versions | Python 3.13 base image; PostgreSQL 18 (volume mounted at `/var/lib/postgresql`, the 18+ layout). | Latest versions with wheels for both amd64 (VPS) and arm64 (dev machine). |
| 2026-10-28 | Fonts | Inter (UI) and Noto Sans JP self-hosted via Fontsource; the Japanese font is split by unicode-range, so it only downloads when Japanese text is on screen. | "Loaded only when needed" without extra code. |
| 2026-10-28 | Flags | Inline SVG flags instead of emoji. | Windows doesn't render flag emoji. |
| 2026-10-28 | Web push | VAPID keys generated on first boot when not in `.env`; reminders sent hourly at each user's chosen local hour if they haven't practised that day. | Zero-config push. |
